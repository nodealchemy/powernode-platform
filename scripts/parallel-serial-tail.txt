# Specs that scripts/parallel-rspec.sh does NOT run inside the parallel phase. They run afterwards, in
# one process, on lane __p1 (<prefix>1) (the "serial tail"). One repo-relative path per line; # starts a comment.
#
# A spec belongs here when it touches state that N processes SHARE even though each process has its own
# Postgres database and Redis lane: a fixed path under the checkout's tmp/ (the working directory is
# one for every process), or a database strategy that is expensive or order-sensitive. No spec is edited
# to get here; moving a file out means making it parallel-safe first. server/spec/lint/
# parallel_serial_tail_spec.rb fails when a spec matching one of the rules below is missing from this list.
#
# --- DatabaseCleaner :truncation (`truncation: true`, `type: :performance`, `:integration` tags) --------
# Per-DB these cannot deadlock one another, but each example truncates every table of its lane's DB, and
# the strategy exists to serve threads that need COMMITTED data: keep them away from the balanced phase.

server/spec/models/user_factory_role_scope_spec.rb
server/spec/services/platform/status/account_lock_spec.rb
# Not truncation itself, but the same shape: a race on REAL separate connections with COMMITTED rows
# (use_transactional_tests = false, cleaning up after itself) and sleep-timed interleaving, which CPU
# contention in the balanced phase can reorder into a false pass or a flake. (The rule above matches its
# comment's `truncation: true`.)
