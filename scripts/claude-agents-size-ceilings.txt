# Size ceilings for the generated Claude Code agent roster (.claude/agents/powernode/*.md),
# enforced by scripts/check-claude-agents-size.sh (run from check-claude-agents-fresh.sh).
#
# Format: key=value, one per line; `#` comments and blank lines are ignored.
#   max_tools_per_agent  the most entries any one agent's frontmatter `tools:` list may hold
#   max_roster_bytes     the most bytes all agent files together may hold
#
# THESE CEILINGS CAN ONLY BE LOWERED. The check compares each value with the version of
# this file committed at HEAD and FAILS if any ceiling is higher than it was (or a key
# that HEAD has is gone). When the roster shrinks, lower the ceiling to the new value in
# the same commit so the saving is locked in. Do not raise a ceiling to turn a red gate
# green; shrink the roster instead.
#
# Limit: the baseline is HEAD, so the raise check bites on UNCOMMITTED edits (the
# pre-commit gate, a local run). Once a raise is committed, HEAD holds the raised value
# and a later run compares against it. Review changes to this file in the diff.
#
# Initial values: measured on the tree as of 2026-09-27 (122 tools in
# infrastructure-generalist.md; 29 files, 199871 bytes).
# Lowered 2026-10-19 (streamlining campaign C4): the roster is the four thin loaders
# (Ai::ClaudeExport::ThinLoader), 16570 bytes including the granted roles'
# disallowedTools deny list (69 exact names); the largest `tools:` list is
# platform-engineer.md's fixed bootstrap core, 17 entries. The byte ceiling keeps
# ~430 bytes of headroom so a wording tweak does not trip the gate.
max_tools_per_agent=17
max_roster_bytes=17000
