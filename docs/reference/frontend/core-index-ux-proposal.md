## Why this exists

Platform core renders **269 object references, 203 of them dead text**, across **250 surfaces** and
**64 distinct object types** — ~2.3x the system extension. The mechanism is already built and shipped
(`@/shared/components/entity/EntityLink`, `entityRegistry`, `useQueryParamFilter`); core's work is to
**register its types** (verifying permissions against the real controllers) and **swap references**.

## Recommended standard

**Default for every object index surface: an expandable-row index table** (core's `DataTable` + a leading chevron disclosure column).

- The expanded region shows **that object's own scalar/JSON detail inline** — config, status detail, stats, timestamps, identity, success criteria, rationale, etc. No modal round-trip to read an item's own fields.
- **Cross-references to other object types are always links** rendered via the shared `<EntityLink type id label />`, which opens the *target* object's detail surface through the global `EntityReferenceHost`. Never plaintext names/IDs, never the parent's modal showing a foreign object read-only. `EntityLink` already degrades to plain text when the type is unregistered, the id is missing, or the viewer lacks the read permission — safe to drop in anywhere.
- Bulk/lifecycle/row actions live in the row's action cell or the `PageContainer` header — never inside page body content.

**When a detail *modal/drawer* is still allowed:** create/edit **forms**, **management consoles** that mutate child collections (multi-tab CRUD surfaces — provider Models/Credentials, channel settings, role↔user assignment, worker management, budget create/edit), and **execution/approval action surfaces** (execute-team, approval-gate, transfer-session). These are editors, not passive viewers; their read-only field display should still be reachable by expanding the row. Detail **drawers** (skills, knowledge nodes, execution resources) are treated as the **own-detail equivalent of row expansion** — keep them.

**Justified exceptions (stay cards / custom panel / canvas):**
- **Dashboards & summary tiles** (FinOps, AiOps, ROI, monitoring grids, stats-card rows, memory-stat bars, health dashboards).
- **Topology / graph / flow canvases** (knowledge graph, skill graph, MCP studio/flow, mission task graph, agent lineage tree, parallel-execution graph tab).
- **Real-time monitors & live feeds** (activity feed, telemetry stream, circuit-breaker live state).
- **Composers / wizards / NL-brief surfaces** (first-run wizard, new-mission wizard, provisioning plan review, research modal, contract editor).
- **Chat thread / conversation panes** (message threads, session messages, chat window) — these are conversational, not tabular.
- **One-time secret-reveal lists** (API key create/view) where expansion would imply re-display.
- **Hub / page organizers** that only host tabs (no rows of their own).

**Cross-cutting prerequisite (one-time, gates the whole run):** `EntityLink`/registry/host exist in core `shared/` but **core registers zero types today**. Add a `registerEntities('core', [...])` manifest for the high-traffic reference targets — `ai_agent`/`agent`, `agent_team`, `ai_provider`, `skill`, `conversation`, `user`, `workspace`, `mission`, `repository`, `data_source`, `knowledge_node`, `kb_article`, `page`, `marketplace_item`, plus the DevOps/Docker/Swarm/K8s objects (most already route-linked). ~40 plaintext reference sites collapse to one-line `<EntityLink>` swaps once this lands.
